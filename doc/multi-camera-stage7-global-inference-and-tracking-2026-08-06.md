# RK3588多路视觉第七阶段：全局推理控制与轻量目标跟踪

## 1. 本阶段目标

- Qt增加“开启全部推理”和“一键关闭推理”；
- Web增加同等按钮与HTTP接口；
- 全局关闭必须停止调度，而不是只隐藏检测框；
- 在现有自适应推理基础上改善低推理FPS时检测框跳动。

## 2. 全局推理控制

Qt主窗口遍历J7、J8和UC325面板调用统一的推理状态接口。关闭时禁止调度通道
继续接受任务，清除尚未处理的最新帧，丢弃在途但迟到的结果，并清空检测框和
目标ID；摄像头采集和预览保持运行。

Web新增`/inference-all?enabled=0|1`，页面顶部提供对应按钮，状态栏同时显示在线
摄像头数量和正在推理的通道数量。

## 3. 轻量目标跟踪

Qt和Web均加入按类别及IoU匹配的轻量跟踪：

- 同类别检测框IoU不低于0.25时沿用目标ID；
- 旧框权重35%、新框权重65%，降低边框抖动；
- 新目标分配递增ID，显示格式为`类别 #ID 置信度`；
- 全局或单路关闭推理时清空Qt跟踪状态。

它不会额外调用NPU，CPU开销只与每帧少量检测框数量有关。当前实现不是完整
ByteTrack，不处理复杂遮挡、轨迹预测和长时间丢失重关联。若后续确实需要跨遮挡
稳定ID，再升级卡尔曼滤波与ByteTrack状态机。

## 4. 验证项目

1. 三路运行时点击“一键关闭推理”，确认三个NPU状态变为off且框消失；
2. 摄像头预览继续运行，采集FPS不归零；
3. 点击“开启全部推理”，三路恢复检测；
4. Web调用全局接口后，`/status`中三路`detection`同步变化；
5. 同一目标连续移动时`#ID`基本保持一致；
6. 检查RKNPU、IOMMU、RKISP与RKCIF日志无新增故障。

## 5. 板端实测结果

两套程序已同步到`192.168.10.65`并使用板端ARM64 RKNN/RGA库完成Release构建。

Web三路实测：

- 初始三路`detection=true`，J7/J8约9.9 FPS、UC325约15 FPS；
- 调用`/inference-all?enabled=0`后，三路立即变为`detection=false`；
- 三路NPU耗时、推理FPS和目标数量均归零，但摄像头采集FPS继续增长；
- 调用`enabled=1`后，三路检测和NPU统计恢复。

Qt offscreen三路回归中，channel 0、1、2均完成首个推理结果，推理耗时约
22.8～31.2 ms，未发现新增NPU/IOMMU故障。

测试中还复现一次J8底层`select timeout`。当时直接使用`v4l2-ctl`也无法取帧，
证明不是Qt界面或推理开关导致。使用以下命令恢复3A管线后，J8立即恢复30.05 FPS：

```bash
sudo systemctl restart rkaiq_3A.service
```

注意服务名包含下划线`rkaiq_3A`。若以后应用异常退出后单路持续显示
`waiting for frame`，应先确保没有程序占用视频节点，再执行上述恢复命令；仍无效
时再重启板卡。
