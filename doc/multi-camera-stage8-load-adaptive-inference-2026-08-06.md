# RK3588多路视觉第八阶段：多级负载自适应推理

## 1. 优化目的

三路摄像头持续以固定频率进行预处理和推理时，即使画面长期没有目标，也会占用
CPU、RGA、DDR和NPU资源。本阶段在不降低有目标场景响应能力的前提下，使空场景
自动降频，并防止旧检测结果长期停留。

## 2. 已实现策略

Qt和Web使用相同的四级推理频率：

| 连续空检测次数 | 推理间隔倍率 |
|---:|---:|
| 0～2 | 1× |
| 3～9 | 2× |
| 10～29 | 3× |
| ≥30 | 4× |

推理间隔最长限制为1500 ms。检测到任意目标后计数立即归零，并恢复配置频率。
摄像头采集和预览FPS不随之改变。

Qt增加结果保鲜机制：超过`max(2000 ms, 基础推理间隔×8)`未收到新结果时，清除
旧检测框并显示`NPU: waiting result`，避免推理管线异常时显示幽灵框。

## 3. 预期收益

- 空场景稳定后，每路推理调用量最多下降约75%；
- 三路同时运行时为后续第四路及更多输入保留NPU/DDR余量；
- 有目标画面仍以原配置频率检测；
- 不增加模型转换和额外NPU上下文。

实际CPU收益取决于场景。Web仍需为MJPEG输出进行解码、叠框和JPEG编码，因此空
场景CPU降幅不会与NPU调用降幅完全相同。

## 4. 后续优化优先级

1. MPP硬件H.264/H.265编码，替换Web多路软件JPEG编码；
2. RKNN tensor memory/零拷贝可行性验证，减少RGB输入复制；
3. 将轻量IoU跟踪升级为ByteTrack，满足遮挡重关联需求；
4. 扩展第四路前进行24小时温度、DDR、RGA和NPU压力测试。

## 5. 板端构建与实测

2026-08-06已同步到`192.168.10.65`，Qt和Web板端Release构建通过。

Web三路实测时三个画面均存在可检测目标，因此保持基础推理频率：

- J7/J8发布约10 FPS，UC325发布约15 FPS；
- 三路推理开启时Web进程CPU约128.7%，即约占用1.29个CPU核；
- 使用“一键关闭推理”后CPU约40.8%；
- 全局关闭推理使该进程CPU下降约68%，三路摄像头发布FPS保持不变；
- `/status`确认关闭后三路NPU耗时、推理FPS和目标数量均归零。

由于现场画面都有目标，本次没有人为遮挡镜头，未伪造空场景降频收益。后续可将三路
镜头对准无目标静态背景，等待连续30次空结果后，通过状态与CPU采样验证4×间隔。

Qt offscreen三路回归中channel 0/1/2均完成首帧推理，单帧约26.7～36.6 ms，
未发现新增RKNPU/IOMMU/RKISP/RKCIF故障。测试结束后Web和Qt测试进程均已停止。
