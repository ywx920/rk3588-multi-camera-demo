# RK3588多路视觉第六阶段：2×2固定界面、残影修复与自适应推理

## 1. 现场问题

### 1.1 关闭摄像头后偶发残留画面

`FrameWorker`与RKNN worker通过QueuedConnection向UI线程发送数据。用户点击关闭时，
程序虽然立即清空了Pixmap，但关闭前已进入Qt事件队列的`frame_ready`或
`result_ready`仍可能随后执行，再次把旧帧写入界面，因此表现为随机残影。

修复方法是在UI接收端增加状态门控：

- `show_frame()`在通道非活动时直接丢弃迟到帧；
- `show_stats()`在通道非活动时丢弃迟到统计；
- `show_inference()`要求摄像头和推理同时处于开启状态；
- NPU状态与错误回调在关闭后不再覆盖关闭状态；
- Stop和采集异常都会同时清空`current_`、推理结果和Pixmap。

底层仍保持软暂停并继续DQBUF/QBUF，没有重新引入STREAMOFF问题。

### 1.2 指标框大小不同、排版变化

FPS文本较短，而NPU文本会包含耗时、实际FPS、丢帧和目标数量，两个QLabel的
尺寸提示不同，导致指标栏分配不均。

修复后：

- FPS和NPU标签使用相同stretch权重与28像素固定高度；
- 两个指标均居中；
- 状态栏固定26像素高度；
- 卡片固定宽高，长文本不能扩大卡片；
- NPU主界面只显示耗时、FPS、目标数量，完整drop信息保留在Tooltip。

## 2. 固定2×2布局

布局位置固定为：

```text
┌──────────────────┬──────────────────┐
│ J7 · OV13850     │ J8 · OV13850     │
├──────────────────┼──────────────────┤
│ USB · UC325      │ 预留通道          │
└──────────────────┴──────────────────┘
```

所有画面框使用相同16:9固定尺寸，实时画面以`KeepAspectRatio`缩放并自动留黑边。
宽度根据当前屏幕计算，但运行过程中不再变化。右下角预留卡片可用于第四路CSI、
USB或RTSP视频源。

## 3. 下一步优化：自适应推理节流

在已有“最新帧覆盖、禁止排队、公平调度”的基础上加入场景自适应频率：

- 正常或检测到目标时按配置的`inference_fps`运行；
- 连续3次没有检测到目标后，提交间隔自动扩大为2倍；
- 最大间隔限制为1000 ms，避免空场景下完全失去响应；
- 再次检测到目标后立即恢复正常推理频率；
- 开启/关闭摄像头或推理时重置空场景计数。

这样可减少无目标画面的NPU提交量，为后续扩展第四路及更多通道保留资源。该策略
不改变摄像头采集FPS和显示FPS。

代码已同步到`192.168.10.65`并完成板端Release构建。由于测试时板端停留在GDM、
尚未登录GNOME会话，先使用Qt offscreen平台进行了15秒三路并发回归：

- J7、J8、UC325三路采集与推理链路能够同时运行；
- 3个RKNN worker均初始化成功并完成首帧推理；
- 首帧推理耗时约33.1～36.1 ms；
- 测试期间未发现新增RKNPU fault/reset/timeout、IOMMU fault、RKISP timeout或
  RKCIF overflow；
- `timeout`返回124是测试按计划结束，不是应用异常退出。

固定2×2位置、按钮外观和关闭后的视觉清空仍需登录板端GNOME后进行目视验收。
建议每路连续执行10次“关闭摄像头/开启摄像头”和“关闭推理/开启推理”，同时观察
关闭通道是否始终显示“摄像头已关闭”，其他通道的位置和尺寸是否保持不变。
